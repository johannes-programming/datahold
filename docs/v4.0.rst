Overview
--------

This project wraps common mutable data structures for inheritance with modification.

Of course, similar base classes are provided by ``collections``.
They were also the main inspiration for this project.
But they suffer from one principal problem:
They necessitate overriding multiple methods
to effectively customize the data holder.
This project allows creating a customized data holder
by only overriding:

- the ``__frozen__`` method (in any class)
- the ``__init__`` method (in frozen classes)
- the ``__mutate__`` context manager (in mutable classes)

All proper methods and magic methods in the classes of this project
use the ``__frozen__`` method to access the underlying data
(and in the mutable ``Like`` classes the ``__mutate__`` context manager to modify it).
Therefore, overriding these methods alone immediately gives an effectively modified class.
Further overwriting of methods is still possible
and might - depending on the situation - substantially improve performance,
but it is not strictly necessary.
For example, it is possible to create - with only a few lines of code - a ``MutableSetSlot[Item]``
that forces all its items to become strings.

.. code-block:: python

    from collections.abc import Hashable, Iterator
    from contextlib import contextmanager
    from datahold import MutableSetSlot

    class StrSet(MutableSetSlot[Hashable]):

        __slots__ = () # the storage slot of MutableSetSlot is _slot

        @contextmanager
        def __mutate__(self) -> Iterator[set[Hashable]]:
            with super().__mutate__() as data:
                yield data
                strings = set(map(str, data))
                data.clear()
                data.update(strings)

The ``Like`` classes provide the common interfaces.
The ``Slot`` classes are concrete implementations storing immutable snapshots
in a single ``_slot`` attribute.
The mutable implementations make changes to a temporary mutable container
and replace the snapshot when the operation completes successfully.
The frozen implementations expose no mutating operations and support hashing
when their contents are hashable.

Installation
------------

To install ``datahold``, you can use ``pip``.
Open your terminal and run:

.. code-block:: shell

    pip install datahold

Version 4.0 requires Python 3.12 or newer and ``frozendict``.
The latter is installed automatically by ``pip``.

Typing
------

The typing conforms strictly to ``mypy``.

Features
--------

Only members defined directly in each class are listed below; members available solely through inheritance are omitted.

The classes below are defined directly in ``datahold`` and can be imported from it.

``datahold.frozen``, or ``datahold.typing`` submodules in this distribution.

This abstract base class inherits from ``collections.abc.Sized``, ``collections.abc.Iterable[Item]``, and ``collections.abc.Container[object]``.

``class Frozen[FrozenItem]``
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

This protocol inherits from ``collections.abc.Sized``, ``collections.abc.Iterable[FrozenItem]``, ``collections.abc.Container[Never]``, and ``collections.abc.Hashable``.

``__slots__ = ()``
^^^^^^^^^^^^^^^^^^

``__contains__(other: object, /) -> bool``
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

This magic method implements ``other in self``.
It returns ``False`` if the underlying membership check raises ``TypeError``.

.. code-block:: python

    def __contains__(self: Self, other: object, /) -> bool:
        try:
            return other in self.__frozen__()
        except TypeError:
            return False
